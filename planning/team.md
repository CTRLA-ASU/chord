# Team

Every subsystem has an owner and an understudy, so nothing stalls when someone graduates or gets busy. Fill this in at the first meeting and update it each semester.

|---|---|---|---|

| Modules | Module interface, KiCad templates, reviewing member modules | | |
| Docs + onboarding | Docs, skill tree, lending library, Pod of the Month | | |
| Security / compliance | Acceptable-use policy, training, university sign-off | | |

## How work gets reviewed
- **Design changes** that touch the module interface, board plan or a decision go through a *Design change* issue before any work.
- **Board orders** need two reviewer sign-offs: schematic, layout and DFM. No exceptions.
- **New modules** start with a *Module proposal* issue.
- **Every PR** uses the checklist. Owners review PRs in their area.
