# Planning

These files are for the club to fill in and keep current as the project moves. They're starting points, not answers. Change them through pull requests so the history shows who decided what and when.

| File | Use it for |
|---|---|
| [semester-0-plan.md](semester-0-plan.md) | The Spring 2027 plan, week by week, with checkboxes and owners |
| [decisions.md](decisions.md) | Open decisions, who owns each one, and what was decided |
| [team.md](team.md) | Subsystem owners, understudies and how reviews work |
| [rev-a-bring-up.md](rev-a-bring-up.md) | Step-by-step first power-on of our first board, with a results table |

**GitHub templates** (under *New issue* and on every pull request):

| Template | When |
|---|---|
| Module proposal | Before designing any bay module, radio head, pod adapter or cover |
| Design change | Before changing anything in the module interface, the board plan, or a decision already made |
| Pull request checklist | Every PR: docs, schematics, layouts, CAD or firmware |

**How a meeting can use this:**
1. Walk `decisions.md` top to bottom: anything due soon?
2. Tick boxes in the semester plan.
3. Look at new module proposals and design changes.
4. Assign owners to anything blank.
